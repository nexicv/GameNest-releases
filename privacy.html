Privacy

Updated November 22, 2026. This notice covers gamenest.info, the GameNest app, and the GameNest relay.

Visiting the site

The site has no accounts, analytics scripts, or forms that send information to GameNest. GameNest does not set tracking cookies on this site.

GitHub Pages hosts the site. GitHub says it logs and stores visitor IP addresses for security. See the GitHub Pages data collection notice and GitHub Privacy Statement.

The GameNest app

The app has no accounts and no sign-in. When you host or join a lobby, it shares a few details with the people in that lobby.

Your display name is shown to everyone in the lobby you host or join. The host also receives two more things. One is your profile ID, a random identifier that the app creates the first time it runs, keeps on your device, and sends when you join, so the host can recognise your installation. The other is the list of game IDs installed on your device, so the host can tell you when a realtime 3D game needs installing. Board games run on the host, so that list does not decide what you can play.

The app saves what it needs on your device. On desktop that is a settings file in the GameNest folder holding your display name, profile ID, port, capacity, and interface choices. Completed chess games are saved in a games data folder there as standard PGN files, which include the player names. A running realtime 3D match has a small launch file holding its join code, and downloaded game packs and cached art use folders in the same place. macOS keeps these files in Application Support, and Android keeps them in the app's own storage. They stay there until you delete them.

The app contacts GitHub when it checks for updates, which it does once at startup unless you turn that check off, and when it downloads a game pack or an app update you asked for. GitHub receives those requests, including your IP address.

Join codes and the relay

Hosting with a join code, or joining with one, sends the connection through the GameNest relay. The relay receives the IP address of each connection and the six-character join code, and passes lobby and board-game traffic between host and guests without encryption. The app adds no encryption to that traffic, so the relay is in a position to read it. On that connection, guests do not learn the host's address and the host does not learn theirs.

Realtime 3D matches work differently. The game connects directly between the host and each guest over its own encrypted connection, and the relay does not carry that traffic. To start one, the host's app sends each seated guest a join code containing the host's LAN or Tailscale address. A guest receives that address even when it reached the lobby through the relay, and its app saves the code in the launch file for the match.
